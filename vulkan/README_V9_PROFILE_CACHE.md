# JR-Strata-Vulkan V9 — Profile-Driven Production Expert Cache

V8 established that the Xe2 expert kernel is no longer the dominant problem:

- all-VRAM routed MoE is around 0.29–0.30 ms on the representative layers
- one RAM miss among top-10 roughly doubles the layer latency
- format specialization helps VRAM-heavy routes but does essentially nothing
  for all-RAM routes

V9 therefore moves the optimization target from the expert kernel to **cache
residency**.

## V9 scope

V9 connects the real Strata cache inputs to the Vulkan routed engine:

```text
expert-profile.bin (STRP v1)
        +
native_experts.txt (real variable expert sizes)
        ↓
whole-model 48 x 512 residency plan
        ↓
real router Top-10
        ↓
(layer, expert) -> resident VRAM / imported RAM
        ↓
V8 format-specialized Xe2 execution
```

The route bundle's old synthetic `vram_count` placement is ignored by the V9
engine. V9 resolves every routed expert from the whole-model residency table.

The cache planner uses the same 256-byte slot alignment as Strata's
variable-sized expert cache and preserves the profile as a strict ranked prefix.

## 1. Build the V9 engine

```bash
cd /data/strata-lab/JR-Strata-Vulkan

unzip -o JR-Strata-Vulkan-V9-Profile-Driven-Cache.zip

GLSL="$PWD/.tools/build/glslang-15.3.0/StandAlone/glslangValidator"

cmake -S vulkan -B build-vulkan \
  -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DGLSLANG_VALIDATOR="$GLSL"

cmake --build build-vulkan -j"$(nproc)"
```

## 2. Build a real whole-model residency plan

The default 17.22 GiB budget mirrors the established B60 SYCL expert cache
baseline. It is intentionally explicit rather than pretending the current
standalone Vulkan harness already knows how much VRAM the future dense/KV
runtime will consume.

```bash
python3 tools/vulkan_v9_cache_plan.py \
  --budget-gib 17.22
```

Default inputs:

```text
profile:
  /data/strata-lab/Strata/data/expert-profile.bin

native_experts:
  /data/strata-lab/data/packs/swift-iq3_xxs/native_experts.txt

output:
  /data/strata-lab/JR-Strata-Vulkan/data/v9-cache-plan.bin
```

Override any path explicitly if the local pack name differs.

The planner reports:

- resident expert count
- exact cache bytes after 256-byte slot alignment
- raw host-fallback expert bytes
- per-layer resident counts

## 3. Profile-driven routed benchmark

First use the established representative layers:

```bash
export STRATA_GGUF_PY=/data/strata-lab/Strata/third_party/llama.cpp/gguf-py

JR_VK_DEVICE=8086:e211 \
python3 tools/vulkan_v9_profile_bench.py \
  --layers 18,35 \
  --samples 4
```

Every route is generated by the real layer router. Placement comes from the
V9 whole-model residency plan, not from route rank.

Then sample all 48 layers:

```bash
JR_VK_DEVICE=8086:e211 \
python3 tools/vulkan_v9_profile_bench.py \
  --layers all \
  --samples 1
```

This prints the sampled Top-10 hit rate and the 48-layer MoE-only timing budget.

## 4. Score a real production routing trace

Synthetic/random activations are useful for engine integration but are **not**
a workload hit-rate measurement.

For a production-quality hit-rate result, use a routing trace produced by
Strata `--dump-routing` and score it directly:

```bash
python3 tools/vulkan_v9_trace_score.py /path/to/routing-trace.bin
```

That reports global and per-layer hit rates against exactly the same V9
residency plan.

## Important boundary

V9 establishes and benchmarks the **production cache policy and real hit/miss
resolution**. The current route harness still materializes only the selected
experts into its two Vulkan arenas before the timed region, as V8 did.

That is intentional for this gate: it measures steady-state routed compute for
the exact profile-derived hit/miss pattern without spending 17+ GiB of VRAM and
20+ GiB of host RAM merely to prove the policy.

Once the plan and real routing hit rate are known, the next internal V9 step is
to materialize this same table as the long-lived whole-model VRAM/host arenas
and add adaptive replacement/prefetch. The file format and lookup contract in
this milestone are designed to carry straight into that implementation.
